# Budget Integrity Check

The Budget Integrity Check reads the master budget workbook and lists the places
where the budget is likely to be wrong: numbers that should come from a contract
but don't say which, lines copied from last year instead of calculated, numbers
typed where a formula belongs, totals that don't add up, and required costs with
no budget. It checks the **budget itself**. Comparing the budget to actuals is a
separate monthly task (see [Monthly Task Checklist]({% link docs/monthly-tasks/index.md %})).

[Open the Budget Check]({{ site.baseurl }}/assets/budget-check/){: .btn .btn-primary }

{: .note }
> Your file is read inside your browser tab and is never uploaded anywhere. The
> page needs an internet connection the first time it loads, to download the
> checker itself (about 10 seconds).

---

## When to Run It

- While drafting and consolidating the annual master budget before sending it to
  HFC for approval (April–May).
- After every revision of the master during the year, such as a correction or a
  reallocation.
- At FO or finance-staff handoff, to see what you are inheriting.

The full review checklist, including the parts the tool can't check, is in the
[Executives & Staff Guide — Budget Integrity Review](https://ubcgss.github.io/executives_staff_guide/docs/05-financial-officer/governance/budget-process/#budget-integrity-review).

---

## How to Run It

1. Open the current master budget in Excel and let it finish calculating.
2. Save a copy to your computer (**File → Save a Copy**, or **Download** if you
   opened it online). Don't run the check on the shared file while others are
   editing it.
3. Open the [Budget Check]({{ site.baseurl }}/assets/budget-check/) and drop the
   copy onto the page, or click **Choose file**.
4. Read the report on the page, then click **Download report (.md)** to keep it.
   Save it in the budget task folder in Dropbox with the date in its name.

{: .important }
> The check reads the totals Excel saved in the file. If a file was never opened
> and saved in Excel (for example, one generated by a script), the totals are
> missing and the report will say so. Open it in Excel, save, and run it again.

## Reading the Report

Each finding has a **severity**:

- **High:** likely wrong. Fix it, or write down why it is right.
- **Review:** not necessarily wrong. Check it and confirm.

The report has five sections.

### Parameters

Parameters are the fixed numbers the budget is built on: contract rents, the
UBC occupancy charge, honoraria rates, CPI, payroll rates, and the months when
lumpy payments arrive. They live in one table on the **Assumptions** tab, with
these columns:

| Column | What goes in it |
|--------|-----------------|
| Parameter | The name, e.g. "CPP rate" |
| Value | The number (or months), typed. Never a formula or a link |
| Status | Calculated by Excel. Don't type here |
| Valid from, Valid until | The dates the value applies to. Blank means no limit |
| Basis | Contract, Published rate, HFC decision, CPI, or Estimate |
| Source | The document and clause, e.g. "2018 Koerner's agreement, cl. 4(2)" |
| CPI-inflated previous | Calculated: the previous period's value inflated by CPI |
| Notes | Anything else worth knowing |

The first row, **Fiscal year**, holds the fiscal year's start and end dates.
Everything else is checked against those dates.

**One row per period.** When a value changes during the fiscal year, give it
one row for each period, with the same name. CRA payroll rates change on
January 1, so CPP rate has a row for 2026 and a row for 2027. Together they
cover June to May. The budget uses the 2026 row for June to December and the
2027 row for January to May. At budget time CRA hasn't published next year's
rates yet, so enter the current rate with Basis **Estimate**. When the real
rate comes out (usually November), update the value, change Basis to
**Published rate**, and report the revision to Council.

Keep last year's row when a value changes, for example the Council Chair's
$175 before it became $200. It shows as **History** and is the "previous"
value for CPI.

The Status column, and this check, show:

| Status | Severity | Meaning |
|--------|----------|---------|
| No source | High | The Source column is blank |
| Lapses before FY end | High | The value ends before May 31 and no row picks up the next day |
| Starts mid-year | High | The value starts after June 1 and no row covers the days before |
| Differs from CPI-inflated previous | High | Basis is CPI, but the value isn't the previous one inflated by CPI |
| Estimate - confirm | Review | The value is an estimate; replace it when the real one is out |
| No previous to check | Review | Basis is CPI but there is no earlier row to compare with |
| History | — | An earlier period, kept for reference |
| OK | — | Nothing to do |

The check also flags a month that uses a parameter outside its dates (for
example January 2027 linked to the 2026 CPP row), and parameters that no budget
line uses.

### Rolled-forward formulas

These are lines set to last year's budget or actuals times an inflation factor,
for example `=R36*1.02`. That is fine for a small line with nothing better to go
on (office supplies). It is not fine when the workbook already calculates the
line properly on a separate tab, such as FT Staff for salaries or Honoraria for
executive pay. For each finding, either link the line to its calculation tab or
add a note in the Notes column saying the roll-forward is intended.

### Hard-coded numbers

A hard-coded number is one typed where it should be calculated or linked. When
the underlying rate changes, these cells don't update, and nothing warns you.
The check flags:

- numbers inside formulas, such as `=18926*200/175`;
- a typed number in a row or column of formulas, such as one month of
  honoraria typed as `1768.99`;
- a typed number that equals a parameter, such as a rent typed instead of
  linked to the Assumptions tab.

Fix each one by moving the number to the Assumptions tab and linking to it, or
by replacing it with the same formula as its neighbours.

### Internal consistency

Checks that each line's annual amount equals the sum of its months, that every
account code is in the Chart of Accounts tab, that no dashes were typed in place
of numbers, that the Consolidated tab equals the sum of the department tabs, and
that no formula links to another workbook. The budget must work on its own: a
link to another file breaks when that file moves or someone else opens the
budget.

### Required lines

Lists costs the GSS must pay every year that have no budget, such as employer
CPP/EI, WorkSafeBC, the audit, insurance, and the lease.

## What It Doesn't Check

- Whether an amount is reasonable. A line can pass every check and still be the
  wrong number.
- Whether each line's monthly spread matches when the money actually arrives or
  goes out. Check this by hand (see the review checklist).
- Anything about actuals.

## Maintaining the Tool

The page is `assets/budget-check/index.html` and the checks are in
`assets/budget-check/budget_checks.py` in this guide's repository. Tests and
developer notes are in `tools/budget-check/`. If the master's layout changes
(new tabs, moved columns), the checks may need updating and the tests should be
re-run.
